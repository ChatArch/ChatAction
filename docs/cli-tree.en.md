# CLI Tree

`chataction --tree` prints the real Click command tree for the installed version. It is not a handwritten README example; new commands should update the runtime tree, tests, and documentation together.

```text
chataction  # ChatAction action orchestration CLI.
├── --help  # Show this help message.
├── --version  # Show the installed package version.
└── --tree  # Print the registered command tree.
```

## Status {#status}

| Node | Status | Notes |
| --- | --- | --- |
| `--help` | Implemented | Generated by Click. |
| `--version` | Implemented | Reads `chataction.__version__`. |
| `--tree` | Implemented | Rendered from the registered `chataction.cli.main` tree. |
| `hello` | Absent | Template demo commands are not part of the real package interface. |
| Business action subcommands | Not implemented | Future real actions need a reusable Python API plus CLI tests. |

## Update Rules {#update-rules}

- Add reusable Python APIs before visible CLI adapters.
- Keep `--tree` generated from the real registered tree rather than copying static examples.
- Tests should cover `--help`, `--version`, `--tree`, and representative leaf/group commands.
- README, MkDocs, CHANGELOG, and release metadata must stay aligned with the command tree.
